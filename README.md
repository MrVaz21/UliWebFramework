# UliServer

Небольшой асинхронный HTTP/1.1-сервер на чистом Python (`asyncio`), без внешних зависимостей. Проект учебный: HTTP-запросы разбираются вручную из байтов, а маршрутизация делается через декоратор.

## Возможности

- Асинхронная обработка соединений на `asyncio.start_server`
- Регистрация обработчиков через декоратор `@server.Handler(Method, RequestURL)`
- Ручной разбор HTTP-запроса: стартовая строка, заголовки, тело
- Поддержка `Content-Length` и нескольких запросов в одном соединении (keep-alive)
- Корректное закрытие соединения при `Connection: close`
- Стандартные ответы на ошибки: `404 Not Found`, `405 Method Not Allowed`, `503 Service Unavailable`
- Таймаут ожидания данных от клиента (60 секунд по умолчанию)
- Логирование через `logging`

## Требования

- Python 3.10+ (используется синтаксис `dict | None`)
- Сторонние библиотеки не нужны

## Пример использования

```python
import asyncio
from UliServer import UliServer
from HttpMessage import HttpMessage

server = UliServer(host="localhost", port=5000)

@server.Handler(Method="GET", RequestURL="/hello")
async def hello(request):
    return HttpMessage().from_params(
        status_code=200,
        reason="OK",
        headers={"Content-Type": "text/plain; charset=utf-8"},
        body="Hello, world!".encode("utf-8"),
    )

asyncio.run(server.start())
```

Обработчик — это `async`-функция, которая принимает объект запроса (`HttpMessage`) и возвращает объект ответа (`HttpMessage`).

## API

### `UliServer(host, port)`

| Атрибут    | Описание                                           |
|------------|----------------------------------------------------|
| `host`     | Адрес, на котором слушает сервер                   |
| `port`     | Порт                                               |
| `timeout`  | Таймаут чтения от клиента в секундах (по умолч. 60)|

| Метод                         | Описание                                        |
|-------------------------------|-------------------------------------------------|
| `Handler(Method, RequestURL)` | Декоратор для регистрации обработчика маршрута  |
| `await start()`               | Запускает сервер                                |

### `HttpMessage`

| Метод / поле                  | Описание                                                        |
|-------------------------------|-----------------------------------------------------------------|
| `from_bytes(data)`            | Разбирает байты запроса. Возвращает `self` или `None` при ошибке|
| `from_params(...)`            | Создаёт ответ из статуса, причины, заголовков и тела            |
| `calc_in_bytes()`             | Собирает ответ в байты (добавляет `Content-Length` и `Date`)    |
| `default_error_404/405/503()` | Готовые ответы с ошибками                                       |
| `method`, `request_url`       | Метод и путь запроса                                            |
| `headers`                     | Заголовки (у запросов ключи приводятся к нижнему регистру)      |
| `body`                        | Тело сообщения в байтах                                         |

## Как это работает

1. `asyncio.start_server` принимает соединение и передаёт его в `connection_handler`.
2. `user_handler` в цикле читает данные порциями по 1024 байта (с таймаутом) и копит их в буфере.
3. `cut_bytes` ищет конец заголовков (`\r\n\r\n`), по `Content-Length` определяет границы запроса и вырезает готовые запросы из буфера.
4. `message_handler` разбирает запрос, ищет обработчик по ключу `(метод, url)` и отправляет ответ.
5. Если маршрут не найден — `404`; если URL известен, но метод не подходит — `405`; при любой другой ошибке — `503`.

## Ограничения

- Маршрутизация только по точному совпадению пути (без параметров и query-строки)
- Нет поддержки `Transfer-Encoding: chunked`
- Нет HTTPS
- Проект не предназначен для production-использования
